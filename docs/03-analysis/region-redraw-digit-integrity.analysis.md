캐시 잔존은 확인되지 않았다. 효과의 새GUID에 따라 순환 숫자가 달라져 좁은 원래1에서 넓은0이 나올 때 잘리는 현상이 드러났다. 실제 참조625픽셀 중92개 누락을 재현했고 수정 뒤0개다. 합성 좁은1에서도 임시0~9 전부 검증했다.

분리 뒤 투명한 테두리를 배경으로 다시 고르면 남은 붉은 무늬까지 획으로 판단해 마지막 숫자 높이가51px로 늘었다. 분리 당시의 불투명 배경색을 대조 기준으로 사용해40~42px로 안정했다. 이 단계는 숫자 검출만 바꾸며 분리 마스크나 글자 픽셀을 침식하지 않는다.

수동 칸 안의 쉼표가 함께 애니메이션되는 차이도 수정했다. 높이가 충분한 기존 세로 잉크 구간만 칸의 숫자로 계산해 쉼표는 고정 backing에 남긴다. 수동 마스크와 명시한 타임라인 마스크는 그대로 유지한다.

첫 브라우저 비교에서 실제 가격의 작은 crop에 대해 글꼴 가장자리 차이가3.559~3.775%로 기존3.5% 기준을 넘었다. 기준을 바꾸지 않고 앱의 동일한 폰트·크기·중심으로 그린 숫자 atlas를 내장했다. 새 패키지는 CEF의 폰트 모양에 의존하지 않는다. 정착 때는 여전히 원본 숫자를 복사한다. 앱의 원본 글리프나 두께를 변형하지 않는다.

OBS 테스트 한 캡처는 ready 메시지 직후 GPU 첫 화면이 비어 있었고 재실행에서는 정상임을 확인했다. 검사는 첫 비어 있지 않은 화면을 최대1.5초 확인한 뒤 캡처하며 끝내 비어 있으면 실패한다. 사용자 OBS 프로필/장면은 사용하지 않는다.

최종 Core671/WPF507/Chrome183/시계5/실제OBS68/렌더비교155 =1,589개. 렌더 기준은 기존과 동일하게 평균 채널 오차3 미만·차이20 초과 픽셀3.5% 미만이다. 서로 다른 엔진의 완전한 픽셀 일치를 보장하는 기준은 아니다. 원본·실제 crop·캡처·개인작업은 공개하지 않고 수치와 합성 검사 코드를 남긴다.

기존 저장된 분리 마스크는 보존한다. 잘못 저장된 분리 자체를 다시 만들려면 정밀 분리에서 재계산/보정 적용이 필요하다. 배경과 글자가 같은 색이거나 무늬가 모호하면 수동 보정이 필요할 수 있다. OBS 출력은 새 버전에서 다시 내보내야 한다.
