# 방송 자료 갱신 검토
2026-11-06 · 제작자 SunjooAn

## Match Rate 100%

- ImageJob.BroadcastId는 저장/스냅샷/원본 교체에서 유지된다. 새 방송 자료로 복제하는 명시적 동작만 새 ID를 만든다. 기존 작업은 저장 시 ID를 유지하도록 전송 직전에 작업을 저장한다.
- 원본 파일 지문과 길이를 작업에 저장한다. 기준 폴더 안에서 하위 폴더와 파일 이름이 바뀌어도 같은 내용의 이미지를 찾는다. 내용까지 변경되어 지문이 달라지면 개별 원본 연결이나 이미지 교체로 지정한다. 이전 작업에는 파일 지문이 없어 이름이 유일한 원본을 찾는 방식을 함께 사용한다.
- 작업용 PC에서 ID와 수정 버전, 브라우저 패키지, SHA256 목록을 ZIP으로 전송한다. ZIP 경로 탈출, 중복 경로, 손상, 과도한 크기를 거부한다.
- 방송용 관리창은 보관 폴더, ZIP 준비, 별도 미리보기, 반영, 복구, OBS 경로 복사를 제공한다. 별도 서버 없이 로컬 파일로 동작하며 관리창을 닫아도 OBS 페이지의 갱신 감지는 계속된다.
- ID별 entry.html 아래 불변 버전 폴더를 준비한 뒤, 메타데이터를 포함한 pointer.js 한 파일을 원자 교체한다. 실패한 반영은 기존 pointer를 유지한다. 같은 버전 재가져오기와 즉시 반영 재요청을 검사했다.
- 로컬 파일의 서로 다른 프레임 사이 접근 제한을 발견해 직접 객체 접근을 postMessage 전달로 바꿨다. 부모·현재/준비 프레임을 확인하고 허용된 명령/이벤트만 전달한다. 새 프레임의 이미지 준비를 확인한 뒤 교체한다.
- 기본은 반복 경계에서 교체한다. 즉시 반영, 비활성/정지 시 교체, 이전 버전 복구를 제공한다. 교체 화면의 실제 파란 픽셀을 Chromium/OBS 캡처에서 확인했다.
- 실제 OBS 스튜디오 모드의 프리뷰→프로그램 전환, 비활성 대기, 재전환의 재등장과 소스 새로고침 없는 수정본 교체를 확인했다.

방송용 PC의 고정 보관 폴더를 이동하면 OBS의 로컬 파일을 다시 지정해야 한다. 이미지 크기가 달라지면 관리창 안내에 따라 OBS 너비·높이를 확인한다. 예전 OBS 출력은 새 entry.html을 최초 한 번 등록해 전환한다. 기존 원본과 사용자 작업을 보존하며 이전 방송 버전은 보관 폴더에 남긴다.

검증 요약은 docs/verification/v1.4.0/summary.json과 배포 패키지 보고서에 기록한다. 다른 PC의 경로 변화는 분리된 보관 폴더·폴더/파일 이름 변경으로 재현했으며 OBS 재생은 실제 설치된 OBS33의 격리 프로필로 검증했다.
v1.4.1에서는 브라우저 status의 loopIndex로도 반복 경계를 판정한다. 표시 시간이 고정된 1프레임 반복도 지연 반영을 처리하며 1fps/60fps 양쪽을 검증했다.
