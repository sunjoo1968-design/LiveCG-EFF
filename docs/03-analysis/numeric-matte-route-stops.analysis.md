# v1.2.2 검토
2026-11-02 · SunjooAn · PDCA numeric-matte-route-stops

## Match Rate: 100%

사용자의 기능 요청5개 모두 구현했다. 정차와 숫자 분리의 검토 항목은 다음과 같다.

| 요청 | 구현·검증 |
|---|---|
| 정차 정확 입력 | 슬라이더 아래 항상 보이는 초 입력/적용, Enter·포커스 이동, 유효성·예산 초과 롤백·Undo/Redo |
| 이동 조절 삭제 | 지점별 이동 슬라이더와 자동/수동 전환 제거, 기존 총시간을 유지한 경로 길이 자동 배분 |
| 모든 지점 정차 강조 | 출발·경유·도착 정차 시간에만 원, 이름 없음, 이동 시작·마지막 정차 종료 때 사라짐, 0초 통과 제외 |
| 정밀 분리 후 숫자 깨짐 | 입력 분리 알파와 숫자 출력 geometry를 분리, 도형/소프트·명시 타임라인 마스크는 유지, native/JS 같은 자산 |
| 숫자 우선·획 보존 | 숫자·가격 우선 프리셋, 자동 보호색, 옅은 AA 보호, 다중 배경의 모호한 가장자리 원본 유지, 투명 PNG 검정 획 보존 |

재현: 4개의8 숫자를 두 색 무늬 배경에서 분리하고 실제 EffectScene 롤링을 투명 숫자 참조와 비교했다. 저장된 분리 결과는 참조 획6,232픽셀 중2,426개를 잃었다. 숫자 칸은 양쪽4개로 같았으며, RangeMode만 끄면 동일하고 저장 마스크만 흰색으로 대체하면 누락0이었다. 최종 재현은4/4 통과, 저장 분리 롤링 참조 획 누락0이다.

원인은 원래 글자 모양의 저장 마스크가 숫자 렌더 후 다시 적용된 것이다. ShapeCoverage와 numericShape 자산에서 입력 추출 알파를 제외하되, 새 숫자의 도형·소프트와 명시 MaskTrack은 그대로 적용한다. 숫자용 shape는 캐시하고 해제한다. 일반 모션의 기존 마스크 동작은 보존한다.

색상 범위의 자동 보호색 추정이 없을 때 배경 허용오차가 옅은 숫자 가장자리를 지우는 별도 문제도 수정했다. 배경 후보에서 충분히 다른 최다 색 묶음으로 보호색을 추정하고, 보호색-배경 혼합 경계를 우선한다. 복수 배경이 다른 알파로 같은 픽셀을 설명하면 원본 색을 남긴다. 투명 배경의 RGB를 불투명 검정 제거색으로 간주하지 않는다. 침식·획 축소·연결요소 삭제는 사용하지 않는다.

흰 숫자/붉은 무늬와 어두운 가격/밝은 무늬, 쉼표·할인율·1px 선·닫힌 구멍을 검사했다. 원본의 보이는 획 지지영역을 보존하고 원래 배경 재합성 오차는 채널2byte 이내다. 사용자가 그린 수동 패치와 타임라인 마스크를 별도로 확인했다. 배경과 글자가 완전히 같거나 압축 잡음이 모호한 경우 완전 분리를 보장하지 않는다.

브라우저 숫자는 advance 폭 대신 실제 글리프 잉크 bounds 중심으로 정렬하여 native와 맞췄다. 비교 시간은30fps 프레임에 맞췄다. 렌더 비교 기준은 평균 채널 오차3 미만·차이20 초과 픽셀3.5% 미만이며 완전한 픽셀 일치를 뜻하지 않는다.
