# v1.2.3 진단·검증 설계
2026-11-02 · SunjooAn

1. 실제 이미지 경로는 LIVECG_TEST_PRICE_IMAGE 환경 변수로 주입한다. 검사 실패/성공과 숫자 통계만 공개하며 실제 이미지·출력 캡처는 로컬 artifacts에 보관한다. 일반 회귀에는 합성 복합 배경과 숫자를 사용한다.
2. 실제 MainWindow/PreviewControl 포인터로 가격 영역을 그리고 글자·획 보존을 선택해 롤링을 추가한다. 삭제/재지정 뒤 같은 동작을 반복한다. 원래/새 영역의 GUID·부모/역할·배경/분리 설정·숫자 경계와 렌더를 비교한다.
3. 동일한 모델을 기존 EffectScene과 새 EffectScene에서 렌더해 캐시의 영향을 분리한다. 위치±수 픽셀과 글자 보호색 자동/수동·정밀 분리 저장·숫자 칸 수동 재설정의 차이를 비교한다.
4. 재현이 실패하는 지점을 확정한 후 데이터·자동 분리·숫자 칸 검출·합성/프리뷰 중 필요한 부분만 수정한다. 기능 설계와 원인 증거는 진단 후 이 문서에 추가한다. 글자 획 축소/침식으로 문제를 숨기지 않는다.

## 재현 후 확정
- 사용자 제공 가격 파일에서 영역 삭제/재지정6회, 새/기존Scene 비교 모두 같은 출력·새GUID·수동마스크/경계 미상속을 확인했다. 캐시 잔존이 원인이 아니었다.
- 실제 첫 숫자1의 좁은 glyph rect로 넓은 임시0을 잘라 참조625픽셀 중92개가 누락되는 현상을 재현했다. 새 효과 GUID에 따라 순환 숫자가 달라지므로 재지정 후에만 달라진 듯 보일 수 있다.
- 범위 분리 후 투명 배경으로 다시 판단하면 남은 붉은 잡음이 숫자 획으로 계산되어 마지막 숫자 높이가51px까지 늘었다. 분리 당시 불투명 배경색으로 대조하면 실제 높이40~42px로 안정됐다. 분리 픽셀 자체를 지우거나 획을 축소하지 않는다.
- 원래 glyph rect는 그대로 보존한다. DigitRollLayout은 glyph 중심 사이를 경계로 별도 rolling viewport를 만들고 사용자 경계가 있으면 그 경계를 우선한다. 임시0~9가 viewport보다 클 때만 임시 폰트 크기를 비율 유지해 맞춘다. 원본 숫자/크기/두께는 정착 때 그대로 복원한다. fontSizes와rollSlots를 브라우저로 내보내 native와 같은 계산을 사용한다.
- 숫자 칸 편집도 같은 배경 기준과 중심 사이 자동 경계를 사용한다. 자동/수동 편집 결과를 불필요하게 다르게 계산하지 않는다.

- 브라우저 임시 숫자는 native에서 같은 폰트·크기·중심으로 그린 PNG atlas를 내장한다. OS/CEF 글꼴 렌더링 차이를 없애며 원본 숫자 픽셀에는 적용하지 않는다. OBS 검사는 loaded 이후 첫 GPU 프레임이 아직 비었으면 짧게 재확인한 후 비어 있지 않은 캡처를 요구한다.
