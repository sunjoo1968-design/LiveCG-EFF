# v1.4.0 방송 자료 갱신 설계
2026-11-06 · 제작자 SunjooAn

자료 이름/경로와 별도로 ImageJob.BroadcastId를 프로젝트와 복사본에 보존한다. 명시한 새 자료 복제만 새 ID를 부여한다. 이전 프로젝트는 처음 열 때 ID를 부여하며 저장 후 유지한다.
작업 PC는 선택 작업을 BrowserExporter로 렌더한 뒤 ID별 전송 ZIP으로 출력한다. 방송 PC는 같은 앱의 방송 자료 관리창에서 보관 폴더 선택/ZIP 가져오기/미리보기/반영/이전 버전 복구를 제공한다.
방송 보관 위치는 ID별 고정 entry.html이다. 수정본은 불변 revision 폴더에 먼저 준비하며 pointer.js 파일 원자 교체로 반영한다. 고정 페이지는 상대 경로로 pointer를 재확인한다. 새 iframe 자료 로드 확인 후 교체하며 OBS 활성화/가시성/제어 이벤트를 전달한다. 기본은 반복 경계에서 교체하고 즉시 교체도 선택한다. 실패한 자료는 기존 방송을 유지한다. 보관 폴더 자체를 이동하면 OBS 재연결이 필요하다.
검증은 이름/폴더 변경, 동일ID 재반영, 다른ID 분리, ZIP 경로탈출·손상 거부, 반영 전 유지, 원자 pointer/복구, Chromium 로컬 파일 자동 갱신·OBS 이벤트 전달을 포함한다.
원본은 파일 지문과 길이로 폴더 내부 이름 변경을 찾는다. 반영 메타데이터는 pointer.js 한 파일에 포함해 원자 교체한다. 로컬 iframe 통신은 postMessage로 상태/명령을 전달한다.
1프레임 반복은 표시 시간이 일정하므로 status.loopIndex로 실제 반복 횟수 증가도 판정한다.
